# Royal Air Cargo — current development scope

Cargo uses the existing Corin/Aerodrome and the profile's headquarters Steward. It introduces no new building, profession quest, dimension access or free material entitlement. The Royal Gilded Contracts tab supplies reviewed accept, unload, resume and verified-unperformed cancellation actions. The normal default is enabled after the consumption/recovery acceptance below. An existing explicit administrator disable is never silently changed.

Server settings: `serverconfig/kingdomsmp-air-cargo.json`, schema1. Current configurable defaults are wheat64, minimum128powered airborne blocks, reward500coins and a shared5000coin UTC-day pool. These numbers are implementation defaults, not a finalized economy balance table. The item must exist in the live registry and stack to64. Custom-named/component-modified items are preserved rather than accepted as ordinary goods. One accepted contract per player/UTCday pins its terms. Its goods must remain in native aircraft storage throughout recorded travel; removing them resets unfinished evidence and requires departure again from the airfield. Player inventory does not substitute for cargo.

The voyage reuses the authenticated evidence format through an isolated `kingdomsmp_air_cargo.dat`/`.created` identity pair and purpose-specific deterministic IDs. Old dispatch file paths, IDs and saved bytes remain compatible. Travel requires the actual controlling authorized pilot, original registered generation/body, powered native engine/fuel, consecutive airborne server samples, a headquarters landing and a parked unoccupied engine-off airframe. Current normal counter/FTB/OPAC permissions are checked again before unload. No permanent chunk tickets or absence-based aircraft replacement are used.

Unloading has four canonical operations: ACCEPT, RESERVE, DELIVER and CANCEL. Before any goods are removed, RESERVE pins exact pristine source slots/counts and finite reward capacity in the economy journal. The container exchange validates every source before changing any slot, removes exactly the selected quantity and preserves remainders/fuel/equipment; an immediate setter failure attempts to restore the captured selected stacks. The native body receives a ticket receipt and a flushed world checkpoint before DELIVER creates one private coin mail. Saved pending receipts are acknowledged without another debit. An untouched original source can be canceled without goods removal or payment; uncertain, absent, modified or delivered sources cannot be guessed into a cancellation. Pending unloads block native use/packing and paid repair; they resume through the explicit Steward review, not automatic entity-load consumption.

Canonical delivery history retains the prior receipt, original generation/body and exact source debit. Unknown/malformed/mismatched receipts block use and quarantine uncertain economy state. **Production does not automatically consume a completed delivery's apparently older goods on join.** Matching-data restoration or explicit administrative recovery review is required. A private old-body repair rehearsal is separate from this production policy. Keep whole matching world/player/economy identities, seals and archives; do not roll back isolated files or delete receipts.
