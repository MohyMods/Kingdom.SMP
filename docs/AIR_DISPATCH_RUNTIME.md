# Royal Air Dispatch

The existing Tier 6 Aerodrome now offers a daily flight contract at Corin Windlass's Royal Gilded **Contracts** tab. Accept the reviewed terms, board a buyer-registered powered aircraft at the airfield (authorized shared crew count), fly the required airborne distance, land within 48 blocks of the kingdom headquarters, dismount and report to its assigned Steward. Fresh worlds retain their Town Hall/Elara endpoint; legacy worlds use their existing Lodge/Mira endpoint. This introduces no building, dimension or profession unlock and adds none of the unapproved profession quests.

`serverconfig/kingdomsmp-air-dispatch.json` contains versioned configurable numerical defaults: 128 airborne blocks, 500 coins, 5,000 shared reward coins per UTC day. These are testable defaults, not a finalized long-term balance table. Each player can receive one reward per UTC day. A pool is fixed by its first canonical payout; accepting a flight does not reserve payment. If another pilot exhausts the pool before reporting, payment is refused without consuming items or changing a purse. Coins go through the existing private Mailbox; they are not dropped into inventories. No profession XP is awarded.

## Authority and recovery

Clients submit only review/confirm requests through the existing correlated commerce protocol. Flight evidence comes from the actual registered native body, current controlling passenger, real engine/fuel state, server positions and ground/ray checks. Distance counts only consecutive powered airborne samples; first samples, taxiing, coasting, passengers and position discontinuities do not add distance. A sampled airborne leg and actual landing near the saved destination are required. Explicit vanilla entity/player teleport APIs and dimension transfers interrupt unfinished evidence; ordinary movement packets do not. No client coordinates, item NBT, unlocked creative flight or administrator exemption authorizes a reward.

`data/kingdomsmp_air_dispatch.dat` and its `.created` identity companion retain bounded per-pilot evidence tied to the economy identity and deterministic world/pilot/day mission ID. The original registration, generation and entity UUID remain pinned. A replacement, lost registration, revoked access, pending workshop repair, invalid saved marker or unavailable original body cannot authorize reporting. Restarting a mission at Corin explicitly discards its unfinished evidence; server restarts retain saved progress. Unloaded aircraft wait for ordinary world loading. The service acquires no permanent chunk tickets.

Before payment, reporting checks the actual maintained headquarters, assigned living Steward, distance/sight, current FTB Chunks and OPAC interaction permissions and the same original parked aircraft. A verified proof is checkpointed before the financial append. Canonical `AIRCRAFT_FLIGHT_REWARD` history commits the once-per-pilot/day quota, pinned finite shared budget and one private coin delivery together. The existing journal/archive, uncertain-write quarantine and mailbox idempotence remain authoritative. A crash between financial commit and evidence acknowledgement cannot mint a second reward. Missing/malformed evidence pauses dispatch; matching-data recovery is required, while other services and already committed Mailbox deliveries remain usable. Do not delete authority files to guess recovery or roll back isolated world/player/journal files.

`/kingdom admin aircraft inspect` requires OP2 and now reports saved dispatch progress, verification/payment state and today's canonical spend. It is read-only and does not create a mission or financial entitlement.

Reproduce the full native suite with Java 21:

```sh
JAVA_HOME="$PWD/work/toolchains/jdk-21.0.13+9" python3 scripts/test-claims.py \
  --namespace kingdom_smp_flight_tests --mods work/aircraft-test-mods \
  --seed-aircraft-restore-world work/claim-server.bqwf3p_o
```

The source must be a stopped verified private purchased-aircraft fixture; the driver locks/copies it and refuses arbitrary user worlds. `--stage-flight-preview` is restricted to this private namespace and stops after a verified arrival for graphical QA. There is no production mission-completion or fault-injection switch.
