# Contribution transactions and recovery

Defined before enabling consumption. The canonical First Hearth store is a versioned atomic NBT file under world/data, separate from the legacy read-only native kingdom snapshot. An initialization marker prevents a missing ledger from silently becoming a fresh kingdom. All operations run on the server thread; one pending transaction serializes the shared final-resource boundary.

1. Revalidate a server-issued, player/session-bound quote: revision, exact inventory, category, quantity, survival/adventure state and one-use nonce.
2. First checkpoint the current pre-donation player inventory, including a new player’s first save. Then durably prepare the accepted quantity and operation identity before changing any items.
3. Remove only accepted items and set a receipt in the death-persistent player tag. Serialize the complete player through Minecraft's actual `saveWithoutId` API, atomically replace the native player file, force file/directory writes, and read back the receipt and inventory.
4. Atomically commit the contribution, receipt, name and history together. Elect the winner and advance Tier 1 to Tier 2 in the same authoritative progress state. Only then acknowledge success.

On restart, an uncommitted prepared transaction is committed once if its new receipt is in the native player file, or cancelled if the previous receipt remains. Any other receipt or unreadable data fails closed. A failed write quarantines new donations and disconnects the affected player; recovery never blindly removes items again. Player login checks committed receipts, including vanilla fallback saves and the integrated host's separate level.dat player copy. A stale loaded inventory may be reconciled from the matching, verified native player checkpoint; unknown/rolled-back stores are blocked rather than accepted as fresh.

This protocol covers process interruption at its durable boundaries on a functioning local filesystem and ordinary restart/disconnect. Back up the whole world, including ledger, initialization marker, playerdata and level.dat together. Arbitrary partial restores, external editors, power-loss guarantees on storage that ignores force/atomic moves, or other mods rewriting player files outside the server thread are not claimed safe. Financial transactions require their own validation; this donation protocol does not implement a bank.

UI contract: Royal Gilded Contributions / Leaderboard panes; four resource selectors with item icons and numeric counts; request a bounded donation, review the exact accepted quantity, then confirm. Mutation controls wait for correlated replies. Server pushes revision changes to open viewers; clients cannot choose another player's identity, credit, tier or score. Contribution history and deterministic rankings are server projections. Completed First Hearth names its permanent highest contributor and earned Founders’ Lodge construction privilege. Physical reward claim/redemption and construction are not implemented in this checkpoint. Town Hall is reserved for Tier 12.
