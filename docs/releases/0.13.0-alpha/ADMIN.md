# Administration and recovery

Keep `main` and live worlds separate from test fixtures. For a fresh dedicated world, use `/kingdom admin owner <player>` followed by `/kingdom admin owner <player> confirm` as OP4; that owner claims the free Hut in K → Construction. Existing owners cannot be reassigned by this bootstrap. Use normal OP permissions and the secured `/kingdom admin` tree; inspection commands require the operator on site and a separate confirmed review. Inspections validate current geometry, independent FTB/OPAC claims, reservations and prerequisite proofs. They do not grant claim access. Never approve a site the player is not authorized to edit.

Master defaults are generated per world at `serverconfig/kingdomsmp-master-equipment.json`. Edit bounded numeric values while stopped, then restart. Schema and keys are strict; malformed configurations fail closed. Prices, operation limits, lapis/XP costs and cooldowns are configurable. No config grants Master or bypasses claims. Keep that file with its world.

Sandbox supply assistance is disabled by default. In an **isolated disposable test world only**, explicitly create `serverconfig/kingdomsmp-sandbox.json` containing `{"schema":1,"enabled":true,"scope":"isolated_test_world"}`. OP4 can review `/kingdom admin sandbox supplies <player> <item> <count> <reason>` and use its actor-bound confirmation. Only whitelisted ordinary resources are supplied. No currency, equipment, blueprint, source evidence, quest, profession XP or rank is minted. Comprehensive progression/profession/construction sandbox accelerators are not implemented; existing administrative inspection/recovery commands remain available. Never enable this config on the live economy.

Back up the entire stopped world. Canonical economy journals, native player receipts, inventories, XP and affected chunk saves form a matched checkpoint. Wand work saves verified world changes before committing the player's paid inventory receipt; restart either commits the matching paid checkpoint or rolls back the saved pending blocks. An unknown edit or mismatched checkpoint is quarantined rather than guessed or refunded. Restore matching records, not individual files from different times. Preserve forensic copies before repairs.

Lost unredeemed blueprints use existing canonical entitlement recovery; do not clone item tags or delete construction records. Existing structures, unique residents and legacy Lodge profiles are never automatically replaced. Chunk unloading pauses construction and tools; no permanent loading tickets are added.
